# Omni-Intelligence 公共名单

两个程序只维护这一份有效名单：

`%LOCALAPPDATA%/Omni-Intelligence/records.sqlite`

采集端和 EEGQC 直接读写同一个 SQLite 文件。记录、移除状态、评分结果及上传状态都在同一张 records 表中；没有导入请求队列、同步副本或删除确认字段。

## 操作

- 完成采集时登记到公共名单；EEGQC 启动或刷新视图时读取全部未移除记录。
- EEGQC 手动导入的记录也写入这张表，采集端直接读取即可看到。
- 点击“打开 EEGQC”只负责打开／激活窗口，不负责传送名单。
- 任一端移除记录，修改的是公共行的 removed 字段；另一窗口下一次读取就使用这个值。
- 恢复同样直接修改公共行，无需另一程序确认。原始脑电文件与服务器上的数据保留。
- 上传任务启动前检查公共名单。已移除条目不能通过旧任务或父文件夹重新上传；正在处理的任务安全结束或取消后刷新窗口。

## 文件的职责

`records.sqlite` 是唯一名单来源，SQLite 事务处理两个进程同时读写。窗口中的表格只是内存视图，刷新不等于维护另一份名单。

原始 EDF、会话元数据与 EEGQC 上传续传缓存属于数据／执行文件，不是第二份名单。两端不以这些缓存决定记录是否存在；记录的存在、移除和恢复以公共表为准。上传仍须由操作者启动。

采集端启动时只检查一次旧会话目录，给既有数据登记公共行；普通记录页刷新只查询公共文件，完成新会话时才登记新记录。

## 迁移与实现

旧 `Omni-Intelligence/RecordLink/records.sqlite` 自动迁移到企业目录根部。旧文件归档到 backups，评分和移除状态保留。数据库版本为 2，删除了 requested 和 removal_ack 字段。

两个产品包含相同的标准库数据访问实现 `record_link.py`，互不依赖对方内部代码。EEGQC 的 SharedRecordView 负责把公共表显示成现有评测视图；本地窗口激活通道不传送记录。

测试可使用 OMNI_RECORD_HUB 覆盖文件位置，产品默认使用企业目录里的唯一文件。旧版程序不支持新表结构，请使用采集端配置的 EEGQC 版本。
