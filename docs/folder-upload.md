# 上传采集文件夹

## 操作

1. 添加采集文件夹并完成扫描、评分，点击右下角「上传文件夹」。
   无文件、评分未完成或正在评分时按钮置灰；历史待续传任务不能绕过此限制。重启后重新添加原目录并评分，即可继续原批次。
2. 确认目录、文件数及总大小后点击「开始 / 继续」。首次签名由服务生成批次编号；收到后立即保存。
3. 上传后台执行，可关闭弹窗继续使用 GUI。失败、取消或重启后继续原批次；已确认成功的文件跳过，失败或未确认的文件从头 PUT。
4. 所有文件成功并重新核对本地快照后申请完成标记，执行空内容 PUT。文件失败、取消或校验不符不会进入此步骤。

这是整文件 PUT 协议，不再支持单个文件内分片续传。单文件大于 5 GiB 时在联网前提示联系管理员。
空目录继续作为零字节目录对象申请签名；若签名服务不接受尾斜杠路径，会明确失败，不静默漏传。
父子目录去重，同名根目录用稳定摘要区分，保留文件原名与内容。目录链接、特殊文件、源文件变化或缺失会阻止该批次。

## 网络与授权

固定签名入口：`https://eeg-upload.kunpeng.blog`。接口无需令牌或登录，所有请求均不携带 Authorization。

- `GET /health`：无 token，期望 200。
- `POST /v1/uploads/sign`：每次最多 5000 个相对路径，首次不传 uploadId，之后始终传原 ID。
- 已部署服务的签名清单位于 `objects`；客户端同时兼容旧约定的 `files`，两种格式均严格核对数量、路径、对象键和签名地址。
- 文件字节用独立 HTTPS 连接直传服务给出的 TOS putUrl，不经过签名服务器，不携带设备 token，不跟随重定向。
- 只接受固定桶 `xiekp` 的北京 TOS HTTPS 主机及 `eeg/inbox/<uploadId>/` 内与清单匹配的 objectKey。
- 预签名地址仅存在内存，不写入状态。403 时仅为尚未成功的文件重新签名，仍用原 ID；持续失败则等待用户重试。
- `POST /v1/uploads/<uploadId>/complete` 使用空请求体，再对返回的 `_COMPLETE` 地址做空 PUT。

使用系统默认 TLS 验证，不需要 SSH、私有证书或 Cloudflare 凭据。
不再读取 TOS AK/SK、相关环境变量或 `tos-credentials.json`，也不会创建该文件。历史文件不会被自动删除。
不再访问系统凭据管理器；旧版可能保存的凭据不会被读取，也不会自动删除。

## 状态与故障边界

应用数据目录：`%LOCALAPPDATA%\\Omni-Intelligence\\EEGQC`。
`uploads/<本地任务编号>/state.json` 记录服务 uploadId、目录快照、完成文件及状态；本地任务编号不是云端 uploadId。
多窗口通过文件锁互斥，状态原子替换。源码目录内不写状态。

首次签名请求在收到响应前断网或进程退出，服务可能已分配编号，但当前 API 没有幂等请求键或按请求查询接口。
此时客户端禁止自动申请另一个编号。请管理员在服务端确认原编号，再用「恢复编号」继续；不能随便填写。
旧 AK/SK 批次若尚无成功文件，保留本地任务并改用服务分配编号；已有成功文件的旧批次停止自动迁移，交由管理员处理，远端数据不删除。

完成标记 PUT 一旦开始进入短暂的不可取消确认阶段，避免把已提交批次显示成“取消”。
若进程在完成标记提交后、收到响应前异常退出，客户端无法撤回服务器已处理的请求；状态保留为未确认，重试仅在所有文件成功时重新确认同一标记。
这类网络提交的不确定窗口不能由客户端单方面完全消除。

不删除远端对象、不修改桶配置，不触碰 `eeg-external-2026-09-11/`。
源目录确认后发生变化会暂停，不能把新数据悄悄混入旧批次。

## 验证范围

协议、取消、过期续签、分批签名和完成标记通过模拟服务测试。真实文件上传尚需单独联调。
使用新客户端实际采用的 HTTPS 连接方式检查公网健康接口，返回 200；没有绕过验证或尝试私有入口。
