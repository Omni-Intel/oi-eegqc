# 多范式上传与脑电帽适配

EEGQC 主界面接收 ZIP、文件和文件夹，上传进度显示在主界面底部。RSVP 采集包自动选择范式、识别被试和采集 Session，并在后台评分；未通过或无法评分的原始数据仍可上传。

## 选择范式和确认目录

点击主界面的范式按钮，在“上传范式”下拉框选择“自然视听 EEG”或“RSVP 图片 EEG”。下方蓝灰色卡片显示“存储位置 · 来自平台数据库”和完整 COS 目录。确认目录后点击“确定”，回到主界面点击“上传”。程序记住上一次选择，队列按范式分别保存。切换范式后展示该范式的队列；已准备的文件不会自动移到另一个桶。

“刷新目录”重新读取平台配置。无法连接内网时会明确提示；未获得范式和目录前不能开始新上传。客户端通过 HTTPS 接口读取数据库定义，不保存数据库密码。

范式列表来自 PostgreSQL `omni_personnel.capture_paradigms`，通过人员平台 `GET /v1/capture/paradigms` 和签名服务 `GET /v1/uploads/paradigms` 提供。数据库连接方式沿用人员平台 RDS 隧道，不由客户端直连数据库。当前包含：

| 范式 | COS 桶与目录 | 地域 |
| --- | --- | --- |
| AVEEG-20260923 自然视听 EEG | neurolm-1442740494/neuro-lm/data/inbox/ | ap-beijing |
| RSVP-20260924 RSVP 图片 EEG | jianyu-1442740494/rsvp/ | ap-beijing |

客户端不携带长期云密钥。签名服务器根据范式目录选择桶与路径，保留分片上传、暂停、续传和完成回执。视频沿用既有上传状态；其他范式有独立本地队列和服务端账本，选择范式不会把同一文件夹的旧上传编号混用到另一个桶。范式窗口显示实际目标位置；主界面底部显示进度、暂停和继续上传。

## ZIP 与自动入库

### 主试上传 RSVP 数据

1. 启动 EEGQC，点击主界面的范式按钮。选择“RSVP 图片 EEG”，确认存储位置为 `cos://jianyu-1442740494/rsvp/`。
2. 将 ZIP 文件或整个数据文件夹拖入主界面。包含多个 ZIP 的文件夹会自动解压并识别各个被试和原采集 Session；核对识别结果后点击主界面“上传”。
3. 等待识别 Session、评分、扫描核验和上传依次完成。准备阶段正在处理本地文件，此时尚未传输。已有评分且文件未变化时直接复用；只有未评分或文件变化的 Session 才评分。上传准备完成后自动开始传输。
4. 看到“上传和入库完成”才表示原始文件、评分和统计均已提交。若显示“文件已上传，统计待入库”，点击“重试入库”；原始文件不必重新上传。

示例目录 `C:\Users\kunpeng\Documents\data` 中的 13 个 ZIP 属于被试 `13467638`，可整文件夹拖入。请保留原 ZIP，直到上传和入库均完成。

拖入 RSVP ZIP 或包含 ZIP 的文件夹后，程序显示解压进度，读取包里的 `session.json`，匹配平台现有的 8 位被试编号。原 ZIP 保留；重复导入复用已解压文件。评分优先选择 `.float32` 无损信号，EDF 副本保留上传。同一信号的时长不重复计算。

点击“上传”后，文件、事件和完整 `eegqc-report.json` 一起上传。续传队列和数据库只保存评分摘要、最终分数及有效时长，详细窗口证据保存在报告文件中。云端确认文件完成后，程序提交原采集 Session、实际脑电时长、最终评分和有效时长，平台自动写入现有 `task_claims` 与 `capture_session_quality`，更新统计。相同被试、范式、原采集 Session 重复提交只更新同一条记录。平台 Session 使用 UUID，原采集 Session 保存在 `qc_summary.source_session_id`。云目录和数据量由服务端上传账本核实。

“上传和入库完成”表示两个步骤均完成；“文件已上传，统计待入库”表示原始文件已经在云端，点击“重试入库”即可，不会重传已上传文件。平台未找到被试时先核对账号，程序不会创建替代账号。

有效时长采用评分的可用窗口比例：最终分数达到 60 时，实际脑电时长乘以可用窗口比例；低于 60 时为 0。无法评分时分数与有效时长留空，原始文件仍上传。图片呈现的有效数量、注意力结果及事件对齐信息单独保存，不代替脑电质检。

缺少采集 Session 元数据的散装文件仍可上传，不能自动关联被试或生成统计。平台接口为 `POST /v1/capture/imports/resolve` 和 `POST /v1/capture/imports/commit`；上传凭据与数据库密码由服务端管理。

新增 COS 范式时，在范式定义表填写代码、名称、桶、地域和目录，授权签名服务器访问该桶，再刷新客户端列表。更换已有范式的桶或目录前，先完成该范式的待传队列，保留旧桶数据，并重启签名服务使新目标生效。

## 更新和遥测

便携版、安装版均在启动时检查更新，优先使用内网 `https://personnel.intra.omni-intel.cn/updates/av-capture/eegqc-stable.json`，内网不可达时检查 GitHub Releases。默认自动下载，评分、导入、上传进行中或有待续传队列时不会自动重启；待工作结束且上传队列完成后更新并重启，也可点击“立即更新”。设置中可关闭自动下载与更新，启动检查仍会运行。

内网更新替换程序文件，保留便携目录或安装目录、卸载入口、设置、当前文件列表、评分缓存和上传队列。更新助手保存替换前的程序；文件替换失败时恢复旧程序，错误记录位于更新缓存的 `error.txt`。

遥测覆盖程序启动、未捕获异常、后台错误、评分失败、范式读取失败、上传成功／失败、更新下载和应用失败。事件含 EEGQC 版本、便携／安装类型、范式、阶段、异常类型、错误码和代码位置；不发送异常原文、人员邮箱、完整本地路径、原始脑电或长期密钥。事件先写入本机 `telemetry.sqlite`，网络恢复后发送，收到回执才清除。服务端与采集程序共用 `/v1/capture/telemetry`，文件存于 `/var/lib/omni-personnel/capture-telemetry/日期.jsonl`，可通过 `app=EEGQC` 区分。

## 32/64 导联与博睿康

评分按文件实际采样率、物理单位和 EEG 通道数量选择规则，不统一重采样到 250 Hz，也不将其他帽的数据改名成 BCIGO 通道。EDF/BDF 使用文件标签；NPY 可以显式声明通道名或设备布局。

提供的 `things_eeg2_extended/config/devices.yaml` 中，博睿康 JellyFish 配置为 1000 Hz、65 列：59 EEG、ECG、4 个眼电通道和 TRG。`neuracle_things_65` 只映射这套已提供的顺序，不代表所有博睿康 64 导联设备均采用此顺序。真正保存 64 个 EEG 通道的 EDF 同样按实际标签读取。

TRG、TRIGGER、TRIG、ECG 和眼电辅助列不参加 EEG 信号质量评分，原始文件上传时完整保留。BCIGO 32 导联的已有配置保持原样。

博睿康代码的 EDF 输出会将微伏值取整并限制到 ±32768；优先保留并分析同时写出的 `.float32` 和 `.float32.json`，EEGQC 已支持此无损格式。读取其明确的 sample-major 布局、采样率、通道名、单位及采样点数量；尚未封存或长度不符的文件不能评分，但可通过主界面上传到云端。

博睿康事件样本编号从 1 开始，评分窗口样本编号从 0 开始；合并事件时需减 1 一次。采集端的 TRG 回读可以验证数字触发到达对应 EEG 样本，主机呈现时间仍不能证明显示器实际亮起的时刻。文件导入不会擅自移动波形、补延迟或把未知硬件时差标记为已校准。
