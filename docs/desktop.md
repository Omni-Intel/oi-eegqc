# EEGQC 桌面版

Qt Quick / QML 桌面界面，复用现有 Python 独立进程评分核心，完全本地处理，不使用浏览器内核。

## Windows 使用

解压 `OI-EEGQC-Windows-x64.zip` 或运行 `OI-EEGQC-Setup-Windows-x64.exe`。
安装器写入 `%LOCALAPPDATA%\Omni-Intelligence\EEGQC`，不要求管理员。
不做代码签名。远程分发走 GitHub Releases；设置里的「检查更新」只读取最新 release 元数据。

多选或拖入 EDF / BDF / NPY 文件，或直接拖入一个或多个文件夹，再点击「评分」。
文件夹会在后台递归扫描子文件夹，自动筛选支持的文件；扫描期间可取消。
「选择文件」「选择文件夹」为两个独立按钮，调用系统文件选择器。再次选择会追加，重复路径自动去重。
同名文件显示相对路径以区分。目录链接（含符号链接与 Windows 联接）不会递归进入；
无法访问的目录会跳过并提示。空目录会显示未找到支持的文件。
列表显示文件名、0–100 质量分数（GQI）和状态。字母分仍写入报告，界面先不当入库判定。
应用界面的文件名以小写显示，实际文件名及读取路径不变；系统文件选择器仍显示文件原名。
EDF/BDF 按各自文件头读取实际采样率与单位，不重采样到 250 Hz，也不弹出采样参数窗口。
头信息损坏的文件会在评分时失败，不能用手动采样率覆盖文件头。
NPY 本身不记录采样率；导入时先读同目录 sidecar，缺采样率或物理单位再弹出窗口。
导入框不再预填 250，必须输入实际值。窗口会预填 sidecar 里已经读到的字段。
支持整数或小数采样率，已测试 64、128、250、256、500、1000、2000 Hz。
可勾选将同一组参数应用于其余数组文件；参数不同的文件应分别确认。
也可为 `sample.npy` 提供同目录 `sample.json`：

```json
{"sfreq": 500, "unit": "uV", "channels_first": true}
```

已知 SDK 的行序可写 `channel_layout`（例如 `"bcigo_sdk_1.0.2"`），或直接给 `channel_names`。
把强脑音视频 session 文件夹拖进来时，同目录 `metadata.json` 也会被认成参数（采样率、设备类型）；通道数对得上才套 32 导名。
通道表说明见 [channel-layouts.zh-CN.md](channel-layouts.zh-CN.md)。

`sfreq` 与 `unit` 齐全即可自动导入。数组行列方向改在「设置」里，缺省为自动判断；
sidecar 若写了 `channels_first` 仍以文件为准。只缺采样率或单位时仍会弹出窗口，并预填已读到的值。采样率还接受
`sampling_rate` 或 `SamplingFrequency` 字段，多个字段必须一致。
sidecar 里的阻抗或同步误差若存在会一并读取，缺失时不询问、也不编造。
每个文件的声明优先于批量共享参数；无效或冲突的参数会提示并跳过该文件。
悬停分数可查看实际采样率、时长和主要原因。点「查看」或双击已评分的行会打开详情：子项分数（接触、洁净、可用时长、完整性、刺激同步）以及按通道写的说明。
能对上强脑 session 文件夹（`continuous_eeg.npy` + `metadata.json`）时，会自动用采集端通道名，例如「P8 全程为 0」。
低采样率会限制可检测频段，不能解释为
完整频谱质量已验证；对应提示也显示在分数上。

批量摘要为已完成文件的平均 GQI，以及按记录时长加权的可用时间比例（∑ 可用窗时长 / ∑ 记录时长）。
失败及未完成文件不计入这两项，分母仍包含它们的文件个数。
评分途中同时显示进度；删除或追加文件后重新统计，失败重试不会重复计数。

右上角「设置」在窗内展开，可改数组排列（默认自动判断）、电网频率（50 或 60 赫兹，默认 50），
以及是否「全通道」。关闭全通道会立刻打开通道表，勾选后只对选中导联评分；也可再点「选择通道」改勾选。
还没添加文件时通道表为空，取消会回到全通道。修改即时保存。
也可检查 GitHub 上的新版本。有更新时打开安装器下载页，由安装器覆盖本地副本；
检查更新不上传任何脑电文件。不恢复旧版固定评分模式。正式启动后会记住排列、电网和通道勾选；
已完成的文件不会因改设置而自动重评。

默认始终使用核心自适应评分。
文件按顺序在后台评分，单个失败不影响后续；再次点击评分只处理未完成或失败的文件。
评分在独立进程中执行，界面显示准备、读取、检查、评分阶段，以及动态加载条和当前文件耗时；不显示虚假的单文件百分比。
「停止」会终止当前评分进程，保留已完成结果；当前取消的文件可以重新评分。评分中关闭窗口也会取消当前任务。
单文件最多等待 15 分钟（包括进程启动），超时或评分进程异常退出后标记失败并继续队列，允许之后重试。
可多选列表行后按删除键或右键「移除」，也可右键「清空」列表；均不删除磁盘文件。

## 开发与打包

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -e '.[desktop,packaging,dev]'
.venv/Scripts/python -m oi_eegqc.desktop
powershell -ExecutionPolicy Bypass -File scripts/build-desktop.ps1
```

构建脚本要求 Inno Setup 6（验证版本 6.7.3），同时生成 zip 与中文安装器，缺少编译器时会明确失败。
非标准路径可传 `-IsccPath`；已安装依赖时可传 `-SkipDependencies`。
使用 Inno Setup 6.7.3 进行商业分发前应确认其商业许可要求；应用本身不做代码签名。
打与应用版本一致的 tag `v*` 会发布 GitHub Release；手动运行 `.github/workflows/windows-release.yml` 只上传构建产物，不发布 release。
资源文件名必须是 `OI-EEGQC-Setup-Windows-x64.exe` 和 `OI-EEGQC-Windows-x64.zip`，桌面「检查更新」按这个名字认。

安装器使用固定应用标识，覆盖升级沿用安装目录，卸载只移除安装器管理的文件，不删除自行放入的数据或用户设置。
开发验证脚本 `scripts/verify-windows.ps1` 在隔离目录测试旧版安装、新版覆盖、启动、设置检查更新和卸载；检测到已有安装时拒绝运行，避免影响用户副本。

macOS / Linux 可安装相同依赖后运行 `oi-eegqc-desktop`。
二进制需在目标系统运行 `python -m PyInstaller eegqc.spec` 分别构建；
当前交付包仅为 Windows x64，尚未在其他系统验证。

窗口标题为 `Omni-Intelligence EEG Quality Control App`，窗口和可执行文件图标沿用品牌 ICO。
内容区域保留极简列表。控件统一圆角、悬停与键盘焦点反馈；文件列表使用虚拟化视图，支持滚动、多选、右键和删除键。
支持按住控制键追加选择、按住上档键范围选择、全选快捷键，以及方向键移动选择。
文件扫描和参数预检在后台执行，大批量列表分段插入；取消评分继续使用独立进程终止机制。
Qt 使用动态库随包分发；
第三方包元数据与许可证位于 `_internal`，分发时需保留。

窗口启动不加载 NumPy/SciPy/MNE；首次评分时由后台任务按需加载。
首次评分仍需初始化计算依赖。扫描异常会恢复导入控件并允许重试；
退出时先结束当前后台任务，避免运行中的线程被销毁。
异常日志位于系统应用数据目录的 `Omni-Intelligence/EEGQC/logs`，
单个日志最多约 1 MB，保留两个备份，不记录信号数组。
参数文件限制为 64 Ki 字符，避免错误导入巨大的参数文件。
